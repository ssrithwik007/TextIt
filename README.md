# TextIt

> A minimal, fast text vault for storing, editing, and copying text through simple URLs.

TextIt is a lightweight frontend-only web application built around one simple idea: **write something once, give it a URL, and access it whenever you need it.**

Every note has a unique slug and can be accessed through two interfaces:

- `/c/:slug` — normal editor, viewer, and copy interface
- `/p/:slug` — Chromium-style network error page with a hidden Dino copy interaction

No accounts. No login. No custom backend.

---

## Features

- Create a new note automatically from the homepage
- Generate a random URL slug
- Change the slug at any time
- Edit and view plain text
- Automatic saving with debounce
- Manual save with `Ctrl + S` / `Cmd + S`
- Copy text directly to the clipboard
- Share notes through their URL
- Alternate `/p/` Dino mode
- Click the Dino to copy the stored content
- Multiple independent notes
- Direct browser-to-Supabase database access
- Responsive dark minimalistic editor
- Lightweight frontend with no unnecessary services

---

## How It Works

Visiting the homepage:

```text
https://textit.com/
```

automatically creates a new note and redirects to a randomly generated slug:

```text
https://textit.com/c/a8Fk29
```

The same note can then be accessed through:

```text
https://textit.com/c/a8Fk29
https://textit.com/p/a8Fk29
```

The `/c/` route provides the normal editing interface.

The `/p/` route displays a browser-style network error page. The stored content is not displayed, but clicking the Dino copies the note's content to the clipboard.

Both routes access the same Supabase record.

## Routes

| Route | Purpose |
|---|---|

| `/c/:slug` | Normal note editor/viewer |

## Database

TextIt uses a single PostgreSQL table.

### Schema

```sql
create table public.texts (
    id bigint generated by default as identity primary key,
    slug text unique not null,
    content text not null default '',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);
```

### Row structure

```text
texts
├── id
├── slug
├── content
├── created_at
└── updated_at
```

Example:

| id | slug | content |
|---:|---|---|
| 1 | `a8Fk29` | `Hello from TextIt` |
| 2 | `college` | `Some college notes...` |

## Supabase Setup

### 1. Create a Supabase project

Create a project at [Supabase](https://supabase.com/).

### 2. Create the table

Open:

```text
Supabase Dashboard
→ SQL Editor
→ New Query
```

Run:

```sql
create table public.texts (
    id bigint generated by default as identity primary key,
    slug text unique not null,
    content text not null default '',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);
```

### 3. Enable RLS

TextIt intentionally has no authentication or ownership system. Anyone who knows a note's URL can read and edit it.

Enable RLS with public policies:

```sql
alter table public.texts enable row level security;

create policy "Anyone can read texts"
on public.texts
for select
to anon
using (true);

create policy "Anyone can create texts"
on public.texts
for insert
to anon
with check (true);

create policy "Anyone can edit texts"
on public.texts
for update
to anon
using (true)
with check (true);

create policy "Anyone can delete texts"
on public.texts
for delete
to anon
using (true);
```

> **Important:** This is intentionally public. A note URL is not a private credential. Anyone who knows or guesses a slug can access and modify that note.

## Slugs

TextIt uses URL-safe slugs.

Examples:

```text
a8Fk29
college
college-notes
my_notes
notes-2026
```

Recommended validation:

```regex
^[A-Za-z0-9_-]{3,100}$
```

Random slugs should use the browser's cryptographically secure random API rather than `Math.random()`.

If a generated slug already exists, generate another one.

Custom slugs must not overwrite an existing note.

## Saving

Text content is automatically saved after the user stops typing for a short period.

Typical flow:

```text
User types
    ↓
Debounce
    ↓
Supabase update
    ↓
Saved
```

The application should not send a database request for every keystroke.

Users can also manually save with:

```text
Ctrl + S
```

or:

```text
Cmd + S
```

## Copying

The normal editor uses the browser Clipboard API:

```javascript
navigator.clipboard.writeText(content);
```

The `/p/` page uses the same mechanism, but the interaction is hidden behind the Dino.

```text
/p/:slug
     ↓
Load note
     ↓
Display network-error UI
     ↓
Click Dino
     ↓
Copy content
```

The stored text should not be visibly rendered on the `/p/` page.

## Dino Mode

The `/p/` route is the signature TextIt feature.

It recreates the visual style of a Chromium network error page inside a normal webpage.

It should include:

- Light background
- Browser-style typography
- Chromium-like spacing
- Network error messaging
- Dino illustration
- Minimal UI
- No visible TextIt branding
- No visible stored content

The Dino acts as the copy control.

### Important

The Dino page is a **visual recreation**, not an actual browser error page.

It does not manipulate browser chrome or attempt to spoof UI outside the webpage.

## Security

TextIt is intentionally public.

There is no authentication and no concept of ownership.

The following are safe to expose in the frontend:

```text
Supabase project URL
Supabase public/anon/publishable key
```

Never expose:

```text
Supabase service-role key
Supabase secret key
Database password
Other server-side credentials
```

Keep `.env` out of version control:

```gitignore
.env
.env.local
```

### Public access warning

Because the database policies intentionally allow anonymous access:

```text
Anyone who knows a note's URL
        ↓
Can read it
Can edit it
Can change its content
```

Therefore, TextIt should not be used for passwords, API keys, private credentials, or sensitive information.

If the application becomes publicly popular, additional abuse protection/rate limiting should be considered.
